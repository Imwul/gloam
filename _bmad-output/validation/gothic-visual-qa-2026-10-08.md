# 고딕 판형·3440 화면 검증 — 2026-10-08

BMAD Design Thinking의 TEST 단계에서 실제 Chrome 렌더링과 키보드 조작으로 확인했다. 사람을 모집한 플레이·선호 조사는 수행하지 않았다.

## 확정 결과

- 새 재현 스크립트 `scripts/gothic-visual-certification.cjs`의 **165개 검사 모두 통과**. 브라우저 런타임 오류 0개.
- 3440×1440, 1920×1080, 1440×900, 768×1024, 390×844, 340×844에서 플레이·전투·인물·탐사·비술·휴식의 6개 화면을 검사했다. 모든 화면에서 문서 가로 넘침이 없었다.
- 각 폭에서 규칙 검색 초점, 회피 검색, 좁은 목록의 가로 스크롤, 창의 화면 내 배치, 배경 스크롤 잠금, 보이는 키보드 초점, Tab 트랩, Escape 닫기, 원래 버튼으로 초점 복귀를 확인했다.
- 플레이, 실제 카드가 배분된 전투, 규칙 창에서 보이는 텍스트 표본의 계산상 명암 대비 경고 0개. 최저 대비는 밝은 지면의 작은 캠페인 표제 **4.58:1**. 검은 판정 면의 표본 최저 **6.77:1**, 검은 전투 면의 표본 최저 **7.49:1**이다. disabled 조작은 대비 표본에서 제외했다. 전 화면의 모든 픽셀에 대한 접근성 인증을 뜻하지 않는다.
- SVG 성채·가지·네 문양은 `aria-hidden="true"`, `focusable="false"`이며 문양 버튼에는 Cups/Wands/Swords/Coins의 텍스트 이름과 능력치가 남아 있다.

## 3440에서 확인한 구성

기존 1680px 지면·1440px 작업 면의 2열을 **2160px 지면·약1960px 작업 면의 3열**로 바꿨다. 3440px 화면에서 지면은 x=640px에 중앙 정렬되며 바깥 여백은 먹색 선무늬로 지면과 연결된다. 판정·사건/징조·인물/목표를 동시에 참조할 수 있다. 판정·사건 패널은 각각 약656px·625px여서 한 설명문이 화면 폭 전체로 늘어나지 않는다.

긴 인물 기록이 최근 기록을 아래로 밀던 초안을 다시 수정했다. 최종 최근 기록은 y=1242px, 높이158px로 1440px 화면 안에 전체가 보인다. 전투의 짧은 폼 값이 과하게 늘어나는 문제도 수정했다. 최종 목표 입력은900px, 괴수 도감 선택은420px이며 괴수 들이기·라운드 끝내기 버튼이 같은 줄에서 이어진다.

## 모바일과 데스크톱 주요 버튼

인물을 구성한 동일한 샘플 상태로 측정했다. y는 문서 최상단에서의 버튼 상단, 높이는 터치 영역이다. 모바일 390/340에서 판정 버튼은 y=747px, 높이46px로 844px 화면 안에 모두 들어온다. 새 표제와 선 때문에 이전 화면보다 버튼 위치가 아래로 이동했지만 첫 화면에서 판정할 수 있다.

## 시각 확인

3440 플레이·실제 전투, 1920 플레이, 390 플레이·규칙 창을 직접 육안 검토했다. 상아색 지면과 먹색 작업 면, 명조 한글 제목, 실제 blackletter 영어 표제, 로마 장 색인, 이중 인쇄선, 가는 선의 성채·사물·가지가 공통으로 이어진다. 텍스트나 조작을 덮는 그림, 버튼 겹침, 가로로 잘린 문단은 발견하지 않았다. SVG 문양은 작은 크기에서도 명확하게 남으며 그림만으로 기능을 전달하지 않는다.

새 디자인의 분위기가 사용자가 기대한 고딕 느낌에 충분한지, 장시간 플레이의 피로가 줄었는지는 실제 사용자 피드백으로 확인할 부분이다.

## 재현·증거

```sh
GLOAM_PLAYWRIGHT_MODULE=/path/to/playwright node scripts/gothic-visual-certification.cjs http://127.0.0.1:5190/ _bmad-output/validation/gothic
```

실행에는 개발 서버와 Playwright, Chrome이 필요하다. Chrome 경로는 `GLOAM_CHROME_PATH`로 지정할 수 있다. 스크립트는 고립된 브라우저 프로필에 샘플 인물·카드를 만들며 실제 사용자의 저장 상태를 변경하지 않는다.
