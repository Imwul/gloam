## 남는 수동 범위와 원문의 모호성

1. **모든 규칙의 자동 집행은 아니다.** 전투 격자 좌표·사거리·대응 시점·재능과 비술 물품의 지속/횟수/면역·구매 성공 뒤 소유 확정·고용인의 주급 주기는 심판과 직접 관리한다. 이를 자동 구현 완료로 표시하지 않는다.
2. **전투 주문:** p.31은 적에게 영향을 줄 때 대항 완드, p.38은 전투 주문 전반에 대항 완드를 적는다. 앱은 적 대상 계산을 제공하고 빠른 참조에서 차이를 설명한다. 비적대 주문의 판정 여부는 심판 확인이 필요하다.
3. **대 아르카나 0 단어:** p.39에는 0의 단어가 있지만 p.7의 심판 덱은 I–XXI이고 광대는 플레이어 덱에 속한다. 0을 심판 덱에 중복 삽입하지 않는다. 표와 명시적 단어 기록 경로는 제공하며 최초 무작위 획득 방식을 임의 발명하지 않는다.
4. **특수 물품:** p.57의 방어 등급 표현 등을 일반 AP 수치로 임의 변환하지 않는다. 예를 들어 Caladbolg의 부상 효과 면제, Dáinsleif의 치유 불가 등은 현재 수동 적용 범위이다.
5. **자료와 자동화 구분:** 제공된 원문·참조 색인의 존재는 실제 계산이 해당 규칙을 모두 집행한다는 뜻이 아니다. 그래서 색인 UI와 테스트 이름을 정정했다.

## 이번 실행의 검증 범위

`src/rules.test.ts`, `src/certification.test.ts`, `src/rulebook/referenceIndex.test.ts`와 새 회귀 검사를 실행했다. 총 58개(기존 31개, 규칙 회귀 18개, App DOM 통합 9개), 5개 파일이 통과했다. `src/gameplay.test.ts`는 원문 전제조건·경계·저장 복원을, `src/App.integration.test.tsx`는 실제 App 컴포넌트의 버튼·필드·저장·복원을 검사한다. 통합 검사는 메모리 DOM·격리 저장소를 사용한다. TypeScript·Vite 운영 빌드와 ESLint도 통과했다.

Mac 잠금 해제 뒤 별도의 로컬 주소 `127.0.0.1:5191`에서 Safari로 확인했다. 검증용 인물을 앱에서 만들었으며 운영 사이트의 캠페인 저장소는 사용하지 않았다.

- 비술: 생성 천직 Mystic의 Magick 배정, 처음 단어 한 쌍 뒤 버튼 비활성화와 새로고침 후 유지.
- 연금술: 준비 조건 → 한 경점 경과 → 완드 판정·밀어붙이기 성공 → 제출한 조제물 1회분 기록 → 새로고침 후 중복 기록 차단.
- 갑옷: Swords 2 인물의 몸통 목록에서 투구 제외·소드 3 갑옷 비활성화. 머리로 바꾸면 투구·방패만 표시.
- 지도: 16칸에서 24칸으로 확장, 심판 카드 배치, 새로고침 뒤 24개 메모 필드와 배치한 카드 유지.
- 규칙 접근: 전역 버튼 한 번으로 빠른 참조 열기, 페이지별 전투·갑옷·시간·비술·지도 항목 확인. 원하는 항목 선택까지 두 번의 클릭이다.
- 시각: Safari 응답형 모드 390×800, 2560×1440과 실제 3440×1440 전체 화면을 확인했다. 모바일 한 열·넓은 화면 두 열, 고딕 제목·색상·44px 입력/선택창을 유지했다. Safari 응답형 모드는 3440 입력을 2560으로 제한하므로 3440 검증에는 실제 전체 화면을 사용했다. 증거는 `validation/rulebook-audit-2026-10-15/`에 보관한다.

이전 감사의 128/165개 브라우저 사례는 이번 검사 수에 합산하지 않는다. 네이티브 파일 선택 자동화에서는 JSON 파일 가져오기를 완료하지 못했으므로 해당 경로의 Safari 검증은 미완료다. 기존 저장 복원은 실제 새로고침과 App DOM 통합 검사로 확인했다. 암호화 원문 파일은 변경하지 않았으며, 암호가 필요한 복호화 회귀 검사는 이번에 재실행하지 않았다. 모바일의 모든 화면·실제 기기 터치·모든 심판 판단을 검증했다고 주장하지 않는다.

## 사용자 추가 피드백: 내부 여백

규칙 검토 이후 사용자가 시간·회차 화면의 여백 부족을 캡처로 지적했다. BMAD CIS 디자인 씽킹으로 시작/정산 절차를 묶고 간격을 수정했다. 상태와 시작 버튼 사이 16px, 정산 영역 앞 28px와 내부 상단 24px를 적용하고 체크박스를 묶었다. 공통 폼의 행·열 간격, 버튼 행과 소제목 사이 간격, 1280px 상태 표시줄의 좌우 여백도 함께 수정했다.

실제 인앱 브라우저의 390×844·3440×1440에서 상태→버튼 16px, 시작 버튼→정산 제목 53px, 선택창 44px와 가로 넘침 없음을 확인했다. 1280px 비술·전투·인물·플레이에서도 가로 넘침을 검사했다. 이 추가 검증은 앞선 인쇄 분위기·폭 검사와 구분한다. 상세 과정은 `design-thinking-session-spacing-2026-10-15.md`, 실측은 검증 폴더의 `spacing-layout-measurements.json`에 기록한다.
