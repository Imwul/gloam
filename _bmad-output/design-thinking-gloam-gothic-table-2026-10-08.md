# Design Thinking Session: Gloam — 고딕 플레이 장부

**Date:** 2026-10-08

**Facilitator:** Codex · BMAD Creative Intelligence Suite

**Design Challenge:** 룰북의 고딕 시각 정체성을 되살리면서 실제 플레이 탁자의 빠른 조작과 읽기 편의를 보존한다.

사용자가 디자인 씽킹 스킬을 명시적으로 요청했다. 앞선 요청의 “중간 승인을 기다리지 말고 분석 → 설계 → 구현 → 검증까지 자율적으로 진행”을 유지하여 BMAD 각 단계의 별도 승인 대기를 생략했다. 이 기록은 이전 기능·정보 구조 검토 세션을 덮어쓰지 않는다. 사람을 대상으로 한 인터뷰·사용성 검사·A/B 검사를 수행한 것으로 해석하지 않는다.

---

## 🎯 Design Challenge

새 플레이 탁자는 판정·사건·징조·목표·규칙 접근을 정돈했지만, 사용자는 “룰북 자체의 디자인 고려, 어딘가 고딕스러운 느낌이 하나도 없어 사이트 디자인에”라고 지적했다. 룰북이 가진 판화·blackletter·성채·타로의 분위기가 로고에만 남고, 화면 전체는 연한 녹색의 일반적인 대시보드처럼 보이는 문제가 있다.

룰북에서 실제로 확인되는 시각 언어를 추출하고, 그것을 화면의 재료·서체·문양·구획·조작 위계에 적용한다. 대상은 모바일에서 판정을 뽑는 플레이어와 데스크톱에서 인물·사건·징조를 동시에 보는 심판이다. 3440px 화면에서도 가운데 작은 카드만 남는 판형을 피하고, 긴 본문은 짧은 읽기 폭을 유지한다. 색만 어둡게 만드는 방식에 머물지 않는다.

## 👥 EMPATHIZE: Understanding Users

### User Insights

- **직접 받은 사실:** 사용자는 현재 웹앱에 고딕스러운 느낌이 없다고 판단하며 룰북 자체의 디자인을 고려하라고 요청했다.
- **앞선 요청에서 확인한 목적:** 실제 플레이 중 빠르고 자연스러운 도구여야 하며, 기존 레이아웃·디자인 결정은 제약이 아니다.
- **출처를 구분한 추론:** 사용자는 게임 세계에 들어온 느낌과 플레이 효율을 함께 원한다. 이는 위 요청과 책의 외관을 연결한 디자인 해석이며 추가 인터뷰 결과가 아니다.
- **사용 맥락 가정:** 모바일에서는 한 손으로 문양 선택·카드 뽑기·결의·규칙 열기를 수행하고, 넓은 데스크톱에서는 여러 기록을 동시에 참조한다. 사람의 행동 관찰로 검증한 가정은 아니다.

선택한 공감 방법은 **Empathy Mapping**, **Journey Mapping**, **Jobs to be Done**이다. 직접 피드백과 실제 화면의 관찰을 우선하고, 생각과 감정은 가설로 표기한다. 관찰을 분류하는 데 **Affinity Clustering**을 함께 사용했다.

원본 `Gloam1.02.pdf`의 60쪽 전체를 실제 PDF에서 렌더링한 contact sheet로 시각 검토했다. 표지 p. 1, 판정 p. 8, Herald p. 18, 부상 p. 32, 결의 p. 34, 인물지 p. 60을 확대 확인했다. PDF 물리 페이지를 기준으로 인용한다. [독립 시각 관찰](gothic-rulebook-visual-reference-2026-10-08.md)에 세부 근거를 기록했다.

## 🎨 DEFINE: Frame the Problem

### Point of View Statement

Gloam 플레이어와 심판은 판정·기록·규칙을 빠르게 다루는 도구 안에서도 룰북의 고딕 타로 세계를 알아볼 수 있어야 한다. 책의 정체성이 로고 한 곳에만 남으면 화면이 게임과 무관한 대시보드처럼 보이고, 반대로 모든 면을 과하게 장식하면 실제 플레이가 느려지기 때문이다.

### How Might We Questions

1. 어떻게 표지의 먹색·판화·blackletter를 긴 규칙을 읽는 밝은 지면과 함께 사용할 수 있을까?
2. 어떻게 네 문양과 판정 버튼이 타로 세계의 물건으로 보이면서도 즉시 조작할 수 있을까?
3. 어떻게 모바일의 짧은 작업 흐름과 3440px의 동시 참조를 하나의 일관된 판형으로 다룰까?
4. 어떻게 원문 그림을 복제하지 않고 가지·무기·아치·장부의 편집 문법을 살릴까?
5. 어떻게 새로운 시각 체계가 기존의 규칙 접근·동작 수·키보드 초점을 악화시키지 않는지 확인할까?

### Key Insights

기능적 작업은 ‘판정과 기록을 놓치지 않는다’, 감정적 작업은 ‘룰북 속 모험의 연장으로 느낀다’이다. 두 작업은 공존해야 한다. 원문은 표지에 매우 강한 장식을 사용하지만 실제 규칙 지면은 조용하고 밝다. 이를 외곽·표제와 읽는 면의 역할 분리로 옮기는 것이 원문에 근거한 해석이다.

주요 문제군은 **정체성의 단절**, **동일한 둥근 카드의 반복**, **화면 폭과 작업 동시성**, **장식과 가독성의 균형**이다. 따라서 새로운 정보 구조를 다시 갈아엎기보다, 기존 플레이 탁자에 인쇄 지면의 일관된 시각 체계와 적절한 반응형 판형을 적용한다.

## 💡 IDEATE: Generate Solutions

### Selected Methods

**Brainstorming**으로 18개 아이디어를 모으고, **SCAMPER Design**으로 현재 둥근 카드·녹색 강조·넓은 빈 공간의 대안을 만들었다. **Analogous Inspiration**은 제공된 책의 표지·천직 지면·인물지를 각각 대안으로 삼았다. **Provotype Sketching**으로 ‘전부 먹색 비술서’와 ‘그대로 옮긴 목판 지면’을 극단안으로 비교했다. 아이디어를 정체성·지면·조작·반응형 네 군으로 묶었다.

### Generated Ideas

1. 화면 바깥을 표지의 먹색처럼 만들고 본문을 상아색 인쇄지로 둔다.
2. 주요 판정 면에 제한된 먹색 판을 사용해 다음 행동을 강조한다.
3. 장 제목 위에 짧은 blackletter 영어 색인을 둔다.
4. 한글 장 제목은 Hahmlet 명조를 쓰고 작은 조작은 읽기 쉬운 본문 서체를 유지한다.
5. 네 문양에 original SVG 선화 아이콘을 사용한다.
6. 선택한 문양은 배경색뿐 아니라 선 굵기·명시적 상태로 구분한다.
7. 패널의 둥근 모서리를 줄이고 장부형 직선·이중선을 사용한다.
8. 원문 가지 머리선을 해석한 가시·나뭇가지 구분선을 만든다.
9. 아치 모양의 표식을 장 표제에만 배치한다.
10. 숫자를 장부의 큰 수치처럼 보여 결의·이동력·시간을 빨리 읽게 한다.
11. 목표·본능·인물 기록은 밝은 면으로 묶는다.
12. 비술·전투·징조의 먹색 정도를 더 강하게 한다.
13. 위쪽을 고문서 표제·갈피처럼 표현하되 실제 내비게이션 이름은 유지한다.
14. 적색은 부상·위험, 황동색은 선택·주요 행동에 제한한다.
15. 3440px에서 지면 2160px·내용 1960px를 사용하고 작업 3열을 펼친다.
16. 3440px에서 판정 / 사건·징조 / 인물·목표를 동시에 보이게 한다.
17. 보통 데스크톱은 2열, 모바일은 1열로 같은 구획을 순서대로 읽게 한다.
18. 질감은 본문을 덮는 이미지 대신 주변 선·미세한 배경으로 제한하고 움직임을 사용하지 않는다.

### Top Concepts

평가는 디자인 판단을 명시하기 위한 도구이며 실험으로 얻은 점수가 아니다. 1–5점, 책과의 연결 35%, 플레이 가독성 30%, 조작 명확성 20%, 다양한 화면 적합성 15%로 비교했다.

| 개념 | 책 연결 | 가독성 | 조작 | 화면 적합 | 가중 평가 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 고딕 인쇄 플레이 장부: 먹색 외곽 + 밝은 장부 + 제한된 검은 작업 면 | 5 | 5 | 5 | 5 | 5.00 |
| 전부 먹색 비술서: 전체 어둠·상아 글자·의례적 장식 | 3 | 3 | 4 | 3 | 3.20 |
| 목판 룰북 판형: 흑백 밝은 면과 촘촘한 장식 지면을 충실하게 재현 | 5 | 4 | 3 | 3 | 4.00 |

**선택: 고딕 인쇄 플레이 장부.** 원문 표지의 강한 첫인상과 본문·인물지의 밝고 실용적인 성격을 함께 반영한다. 목판 판형의 서체·선·문양을 채택하고, 비술서의 먹색 강조는 중요 작업과 외곽에 제한한다. 원문의 보호되는 그림을 추출하여 재사용하지 않고 새로운 SVG 문양과 CSS 선으로 구현한다.

## 🛠️ PROTOTYPE: Make Ideas Tangible

### Prototype Approach

**Storyboarding**으로 첫 화면→문양 선택→판정→결의→규칙→목표 복귀의 조작을 유지하는지 확인한다. **Paper Prototyping**에 해당하는 판형 비교를 1열·2열·3열의 CSS 골격으로 만들고, 실제 상태와 입력이 동작하는 웹앱에 적용한다. 가짜 카드 결과·저장을 사용하지 않고 실제 판정·전투·규칙 상태로 확인한다.

CSS 색·서체·선·간격을 공통 토큰으로 정리하고 기존 작업 요소에 일관되게 적용한다. 원문과 비교하는 시각 확인은 자동화 결과와 별도로 수행한다. 흐름의 구조를 유지한 채 재료와 판형을 바꾸므로 기존 규칙 구현을 고치기 위한 작업과는 범위를 구분한다.

### Prototype Description

- **외곽:** 따뜻한 검정, 상아색 선·blackletter 표제, 성채/아치와 가지를 해석한 짧은 장식.
- **지면:** 상아색 기록지, 진한 먹색 본문, 명조 제목, 장부형 구획과 곧은 선.
- **핵심 조작:** 판정과 선택은 주변보다 강한 대비를 가진다. 한글 동사·수치·초점 표시를 유지한다.
- **문양:** Cups·Wands·Swords·Coins에 새로운 선화 SVG를 사용하며 그림만으로 버튼 뜻을 전달하지 않는다.
- **3440px:** 지면 약 2160px, 내용 약 1960px, 판정 / 사건·징조 / 인물·목표의 3개 작업 열. 개별 설명문은 짧은 읽기 폭을 유지한다.
- **보통 데스크톱:** 2열 작업 면. **모바일:** 1열 작업 면과 터치 가능한 버튼; 장식은 작게 줄여 실제 내용을 가리지 않는다.
- **기타 화면:** 전투·인물·탐사·비술·휴식·보존·규칙 창까지 같은 서체·선·팔레트가 이어진다.

### Key Features to Test

‘고딕 판화 장부’로 읽히는 첫인상, 밝은 면/검은 면의 글자 대비, 네 문양의 선택 구분, 주요 판정 버튼의 가시성, 규칙 창의 가독성과 초점, 3440px의 활용 폭, 모바일의 단어 잘림·터치·가로 넘침, 기존 조작 수와 규칙 결과의 회귀를 확인한다.
