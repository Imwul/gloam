# Problem Solving Session: Gloam 룰북 전체 적용 여부 재검토

**Date:** 2026-10-15
**Problem Solver:** Codex
**Problem Category:** 규칙 충실성·검증 증거
**Workflow:** BMAD CIS `bmad-cis-problem-solving`
**Execution:** 사용자가 기존에 승인한 자율 실행 범위에 따라 YOLO로 진행. 사람 인터뷰나 정식 TEA 워크플로 완료로 보고하지 않는다.

## Problem Definition

### Initial Problem Statement

룰북 내용이 모두 적용되었는지 재점검하고 필요한 수정을 푸시한다.

### Refined Problem Statement

제공된 본문 60쪽, 공식 전투 예시 3쪽, 인물지 1쪽을 규칙의 기준으로 삼아 현재 구현·빠른 참조·검증을 대조한다. 규칙이 참조에 있는 것, 사용자가 기록할 수 있는 것, 앱이 실제 계산하는 것을 구분한다. 동작 오류와 누락을 고치고 원문에 없는 자동화를 만들지 않는다.

### Problem Context

검토 기준 코드는 `556462aa5423622ffd6e4d0cae3e4a14d97a58db`. 기존 2026-10-08 감사와 테스트 결과는 조사 단서이며 이번 버전의 완전성 증거로 재사용하지 않는다. 직접 그린 장식 제거, 44px 선택창, 모바일·3440px 대응이라는 사용자 결정은 유지한다.

### Success Criteria

- 룰북 모든 페이지에 적용 분류와 근거가 있다.
- 일반 판정, 전투, 피해·갑옷, 결의, 생성·성장, 비술, 탐사·시간, 휴식·막간·징조의 규칙을 대조한다.
- 발견한 실제 오작동에는 원문에서 도출한 회귀 검증이 있다.
- 수동 심판 해석과 자동 계산의 경계를 명시한다.
- 현재 검사·빌드와 필요한 브라우저 절차를 통과하고 양 브랜치 푸시·운영 반영을 확인한다.

## Diagnosis and Root Cause Analysis

### Problem Boundaries

일반적인 세계관·심판 조언은 참조 대상이고, 카드·자원·조건·순서가 명시된 규칙은 계산 또는 절차 지원의 대상이다. 본문을 찾아볼 수 있다는 사실만으로 자동 적용 완료라 판정하지 않는다. 제공되지 않은 온라인 판본이나 하우스 룰은 기준으로 도입하지 않는다.

### Investigation Status

원문 64쪽을 다시 읽고 수치·절차와 현재 계산 경로를 대조했다. 기존 31개 단위 테스트는 통과하지만 실제 UI 핸들러의 전제조건을 충분히 검사하지 않는다.

### Root Cause Analysis

Five Whys와 Systems Thinking을 적용했다. 규칙 설명은 존재하지만 계산 버튼이 그 전제조건을 공유하지 않는다. 첫 비술 단어의 임무 제한은 설명에만 있고 뽑기 핸들러는 무제한이다. 연금술 완료 여부는 저장 상태가 아닌 일시적인 폼에 있어 이름 변경과 새로고침으로 해제된다. 피해 계산은 부위와 소드 요구치 없이 AP만 받는다. 인물 생성의 천직 변경은 시작 재능을 누적한다. 결과적으로 텍스트·입력 폼·저장·계산이 같은 규칙 상태를 보지 않는다.

### Contributing Factors / System Dynamics

- 문서의 섹션·표 개수와 장기 저장 모의 검증은 동작 전제조건을 증명하지 않는다.
- 범용 수동 기록과 자동 보상이 같은 버튼에 섞여 있었다.
- 일반 카드 버리기 행동에서도 광대를 일괄 제외해 원문의 ‘아무 카드 버리기’ 경로를 막았다.

## Analysis

추진력은 제공된 원문·기존 보존 자료·즉시 재현 가능한 코드이다. 제약은 심판의 서사·재능·물품 해석을 자동 생성하지 않는 것, 기존 저장과 사용자 디자인 결정을 보존하는 것이다. 온라인 판본이나 새 하우스 룰은 도입하지 않는다.

## Solution Generation

Gap Analysis, Assumption Busting, Failure Mode Analysis로 다음 대안을 비교했다.

1. 원문 페이지별 적용 대조표 작성.
2. 설명만 보강.
3. 첫 비술 단어를 재능·최초 1회로 제한.
4. 임무로 얻은 단어는 별도 명시적 기록 경로 유지.
5. 연금술 시도를 저장되는 판정에 연결.
6. 완료 시도에 1회분만 지급하고 완료 여부 저장.
7. 갑옷의 보호 부위·소드 요구치를 계산과 UI가 함께 사용.
8. 장비 목록과 플레이 중 정보에 요구치·태그 노출.
9. 생성 천직 변경 시 기본 시작 재능만 교체하고 솔로 추가 재능은 보존.
10. 카드 버리기 행동과 판정 행동의 광대 사용 조건 구분.
11. 모든 재능·56개 비술 물품을 별도 자동 효과 엔진으로 구현.
12. 현재 앱을 전면 재작성.

## Evaluation and Recommendation

원문 충실성 40%, 재발 방지 30%, 기존 저장·플레이 보존 20%, 수정 범위 10%로 비교했다. 1·3–10을 채택한다. 설명 보강만으로는 실제 보상을 고치지 못한다. 11은 심판의 조건 해석을 임의 고정할 위험이 있고, 12는 이번 재현 문제의 해결에 필요하지 않다. 해석이 필요한 규칙은 원문 접근과 명시적 수동 기록을 남긴다.

## Implementation Plan

PDCA: 전제조건을 공통 함수로 추출 → 버튼과 저장에 연결 → 원문 기반 경계·재시도·복원 사례 검사 → 브라우저에서 실제 버튼 경로 검증 → 결과를 대조표에 기록한다. 책임자는 Codex이며 사용자가 추가 결정을 해야 하는 새 외부 서비스·유료 도구는 없다. 단계별 완료 증거를 기록하고 시간 추정은 하지 않는다.

## Monitoring and Validation

기존 단위 검사, 신규 규칙 회귀 검사, 빌드·코드 검사, 실제 UI의 첫 단어 재시도·연금술 1회 지급·갑옷 부위 변경을 확인한다. 모바일·3440px에서 새 정보가 넘치거나 44px 입력 높이를 깨면 수정한다. 검증 불가나 원문 모호성은 ‘완료’로 덮지 않고 대조표에 별도 기록한다.

### Workflow Availability

설치된 TEA 스킬은 프로젝트의 `modules.tea` 설정이 없으므로 활성화 단계에서 중단했다. 이 문서는 BMAD CIS 문제 해결 결과이며 정식 TEA 추적성 게이트 완료 보고서가 아니다. 프로젝트 설정을 임의로 채우거나 자동 검사 통과로 가장하지 않았다.

## Implementation and Validation Outcome

첫 주문 단어·연금술·갑옷·생성 재능·광대 버리기·지도 확장의 여섯 문제를 수정했다. 지도의 16칸 한계도 가정이었으며, 원문은 그 제한을 두지 않았다. 규칙 전제조건을 공통 함수로 만들어 버튼 상태와 실제 계산이 같은 조건을 사용하도록 했다.

기존 검사와 새 경계·복원·App 이벤트 검사를 합쳐 58개가 통과했다. 운영 빌드와 ESLint도 통과했다. Safari에서는 비술 한 쌍 제한·조제 1회분·갑옷 부위/요구치·24칸 지도와 새로고침 복원·빠른 참조 접근을 확인했다. 390px 모바일, 2560px 응답형, 실제 3440px 전체 화면에서 시각 배치를 확인했다. 모든 규칙·화면·기기의 자동 검증으로 확대 해석하지 않는다.

48개 본문 대조 행과 두 부록 대조 행에 참조·기록·자동 계산·수동 해석 경계를 남겼다. 모든 본문 페이지를 표에 포함했지만 이를 규칙 자동 적용률로 환산하지 않는다. 자세한 결과와 한계는 `rulebook-coverage-audit-2026-10-15.md`와 검증 JSON에 기록한다.

## Lessons Learned

규칙이 화면에 적혀 있어도 행동 전제조건과 보상 지급 경로가 다르면 실제 적용은 어긋난다. 표·페이지 개수를 세는 검사와 실제 버튼·저장·재시도 검사를 함께 사용해야 한다. 재료나 심판의 판단을 앱이 알 수 없는 경우에는 임의의 자동 해석보다 명시적인 확인·기록·원문 접근을 제공한다.

앞으로 해당 규칙을 바꿀 때 공통 조건과 App 이벤트 회귀 검사를 같이 갱신한다. 새로운 원문 판본·사용자 재현 오류·저장 마이그레이션 변경을 재감사 계기로 삼고, 근거 없는 ‘전체 자동 적용’ 표시는 피한다. `workflow.on_complete`는 실행했으며 추가 지시가 없는 것을 확인했다.
