## 🎯 Design Challenge

사용자의 실제 피드백은 “글씨가 너무 작아”, “이 부분 레이아웃 좀 별로야”, “BMAD 스킬을 사용해봐”이다. 진행 중 “경점이 뭐야?”, “폰트 아직 안 바뀜”이 추가되었다. 마지막 피드백은 크기 변경만으로는 글꼴 자체의 요청을 충족하지 못했다는 근거로 반영한다.

BMAD `bmad` 지식 스캔과 `bmad-cis-design-thinking` 워크플로·설정 해석을 실행했다. 이 문서는 해당 스킬의 템플릿에 따라 공감→정의→발산→프로토타입→검증→반복을 기록한다. 사용자는 중간 승인 없이 구현·검증·푸시까지 요청했으므로 별도의 승인 체크포인트를 기다리지 않는다. 새로운 사용자 인터뷰나 다수 참가자 실험을 수행한 것으로 표현하지 않는다.

## 🎨 DEFINE: Frame the Problem

### Point of View Statement

실제 플레이를 진행하는 사용자는 이야기를 멈추지 않고 현재 상태를 읽어야 한다. 서로 다른 종류의 정보를 작은 한 줄에 압축하고 용어 설명을 생략하면 크기만 키워도 판독 부담은 남는다.

### How Might We Questions

1. 수치 세 종류를 같은 순서와 같은 폭으로 읽게 할 수 있을까?
2. 휴대폰에서도 부상과 시간을 숨기지 않으면서 읽을 수 있을까?
3. 처음 보는 경점의 의미를 별도 검색 없이 이해하게 할 수 있을까?
4. 룰북의 명조 본문을 조작 가능한 크기와 줄 간격으로 옮길 수 있을까?

### Key Insights

주 문제는 작은 크기·서체 불일치·상태 위계·용어 이해가 겹쳐 있다는 것이다. 크기, 구획, 글꼴, 문구를 함께 개선한다. 1/3은 첫 번째 시간대인데 분수로 오해될 수 있다. 룰북 p.50 및 `src/rules.ts`의 원칙은 경점=8시간, 하루=3경점이다.

## 🛠️ PROTOTYPE: Make Ideas Tangible

### Prototype Approach

Role Playing의 작업 시나리오를 이용한 실제 React/CSS 프로토타입. 선택지는 구조 수준에서 비교하고 선택한 안을 실행 가능한 코드로 구현했다. 종이 시안 세 개나 세 개의 완성 UI를 구현했다고 주장하지 않는다.

### Prototype Description

- 모바일 / 기본 / 2200px 이상 본문: 17 / 18 / 21px.
- 설명·라벨: 15 / 16 / 18px, 입력: 17 / 18 / 20px.
- 공통 글꼴: 로컬 `Hahmlet` variable 명조. blackletter 로고·영어 장 제목은 유지.
- 상태 수치: 28 / 30 / 36px, 라벨과 보조 정보는 별도 줄.
- 인물 정보 + 결의·이동력·시간의 같은 폭 구획. 모바일은 인물 행 다음에 세 구획.
- ‘1/3 경점’ → ‘1번째 경점’; 가까운 곳에 ‘8시간 단위’, 휴식에는 ‘1경점 = 8시간 · 하루 3경점’.
- 기존 44px 선택창 높이 유지. 새 손그림 없음.
- 360px 이하 탐색은 세 열 두 행으로 배치해 글씨 축소 없이 접근.

### Key Features to Test

상태 세 구획의 폭·높이, 정보 누락, 글꼴의 실제 computed style, 320/390/1280/3440px 넘침, 모든 탭의 선택창 높이, 세 상태에서 해당 규칙까지 한 번 클릭, 기존 플레이 회귀 검사.

## ✅ TEST: Validate with Users

### Testing Plan

사용자 피드백은 위 실제 메시지에 한정한다. 구현 후 에이전트가 브라우저에서 작업을 따라가며 스타일·기하 측정과 스크린샷으로 검토한다. 여러 사용자 검증이나 읽기 속도 향상률을 꾸며내지 않는다. 상세 결과는 `_bmad-output/validation/typography-2026-10-15/`에 기록한다.

### User Feedback

이미 수집한 실제 피드백을 프로토타입 수정에 반영했다. 변경 후 사용자 만족도는 아직 확인하지 않았다.

### Key Learnings

브라우저에서 4개 폭 × 6개 탭, 총 24개 조합을 검증했다. 모두 document scrollWidth가 clientWidth를 넘지 않고 화면 밖 조작 요소가 없었다. 실제 computed style은 Hahmlet이며 본문은 17/18/21px, 상태 수치는 28/30/36px이다. 모든 표시된 select 높이는 44px이다. 세 상태 구획은 각 폭에서 같은 높이·폭(소수점 반올림 차이 0.02px 이내)을 유지했다.

390px와 3440px에서 결의·이동력·시간 각각의 규칙 열기를 검증했고 모두 한 번 클릭으로 해당 규칙 제목을 표시했다(6건). 모바일 세 구획의 보조 정보는 같은 시작선에 놓고 시간 설명의 추가 줄만 아래로 흐르게 조정했다. 320px에서 기존 body min-width와 스크롤바가 충돌해 15px 가로 넘침을 만든 것을 찾아 min-width를 제거했다. 아주 좁은 탐색에는 3열 2행을 적용했다.

글자 크기만 조정한 첫 프로토타입은 사용자의 추가 피드백으로 서체 자체 변경까지 수정되었다. 가로 넘침 없음과 한 번 클릭 접근은 측정했으나 실제 읽기 속도·인지 부하 개선률 및 사용자의 최종 만족도는 아직 측정하지 않았다.
